# 文风提取器 writing-style-extractor

**从一篇到一批样本，逆向工程出有证据、可执行、经真实试写验收的文风规则包或配套文风包。**

[English](./README.en.md) ｜ [SKILL.md](./SKILL.md) ｜ [方法论全文](./references/methodology.md)

---

## 为什么需要它

「模仿我的文风」是一个愿望，不是一个约束——AI 只服从具体、可测试的规则。常见做法有两种，各有各的坑：

- **喂几篇范文**：模型会抄走原作者的自称、栏目标签、标志性收尾句这些身份元素，而且效果不稳定；
- **跑一次「风格分析」**：产出的结论无法核对——说「作者善用短句」，证据在哪篇哪段、出现频率多少，全凭模型一张嘴，且从未被验收过。

本 skill 把「读起来像谁」这种**感觉**，翻译成一份**可执行的说明书**：每条动作都要回到样本的段落与引文，生成的文风包要经过真实试写。样本充足时，再走对照试验、盲评、留出复测和验收门槛。

## 样本少也能开始：三档路线

| 样本量 | 路线 | 产出 | 能做什么 | 不能声称 |
|---|---|---|---|---|
| **1 篇** | 单篇候选 | 配套文风包 | 从这一篇提炼可观察动作，在同类型新材料上试写 | 作者整体风格、跨题材泛化、频率统计、完整验证 |
| **2-3 篇** | 少样本候选 | 配套文风包 | 比较重复出现的动作，区分核心与条件规则 | 稳定作者特征、最低样本量已确定 |
| **8-10 篇** | 完整验证 | 文风规则包 | 四组对照＋盲评＋留出复测＋五项门槛 | 全部体裁适用 |

三条路线共用同一套证据要求：`S{nn}-P{nn}` 引用必须能回查，`evidence_check.py` 查不到就删。区别只在样本量与验收强度，不靠降低证据标准来「支持少样本」。

### 单篇怎么走

适合：你只看到一篇很喜欢、想复用的文章，先要一个能在同类新材料上试写的包。

1. **生成分析文本**：`P01` 为标题行，正文逐段编号，得到 `S01-P01…`。
2. **提炼可执行动作**：每条动作只引用这一篇的 `S01-Pxx`，标明核心／条件／可选，并区分「文风证据」与「题材事实」。
3. **反推准备要求**：按动作逐条反推需要什么材料、怎样选取、缺少时如何处理；不先写通用准备流程。
4. **生成单篇候选包**：`SKILL.md` ＋ `references/style-contract.json`、`preparation.md`、`rewriting.md`；共享规范里 `sample_count` 为 1。
5. **真实试写**：用一份同类型的新材料跑完整转写，记录本次可用范围与暴露的问题；使用者评价后才谈「候选可用」。

单篇候选的硬边界：

- 不做频率、占比、稳定性推断；「在这篇里出现」不等于「作者常用」。
- 单篇里的偶然写法不得升级为普遍规则；优先核心动作＋条件规则。
- 适用场景限于与本篇同类型的新材料；跨题材、跨体裁、跨平台均未验证。
- 单篇候选不能晋升为正式基线；要晋升，先补样本走完整验证。

## 完整验证路线：五道闸门＋使用观察期

| 阶段 | 做什么 | 产出 | 闸门 |
|---|---|---|---|
| 1 建档与收样 | 界定适用范围；按「6 提炼 + 2 开发验证 + 2 留出」收样本 | 档案说明、样本清单、分析文本 | 用户确认分组与边界 |
| 2 拆解与规则原型 | 统计签名 + 六维度逐篇拆解 → 跨篇比较；规则包 V0.1 | 证据表、规则包 | 证据回查通过 + 用户过目 |
| 3 开发试验 | 3 个任务 × A/B/C/D 四组 = 12 篇生成；盲评；按失败修订表迭代 | 试验记录、盲评表 | 盲评汇总后用户确认修订方向 |
| 4 独立复测 | 冻结规则；3 个全新任务 × 规则方案 vs 范文基线 × 各两次 = 12 篇；评审启用留出真文 | 复测记录、门槛核对表 | 五项验收门槛全部通过 |
| 5 晋升交付 | 产出可部署规则包（含冲突协议与验证边界声明） | 晋升快照 | **必须用户明示确认** |

晋升后进入使用观察期：实际使用中发现的问题记入使用记录，累积到下一轮修订。

四组对照的设计意图：**A** 基础输入 / **B** +范文 / **C** +规则 / **D** +规则+范文。C 对 A 回答「规则本身有没有用」；D 对 B 回答「规则比直接喂范文强在哪」——这是规则包存在的意义，也是复测的强制基线。

### 四个核心机制

1. **证据可回查**。每条观察都带「样本-段落」引用（如 `S01-P05`），`evidence_check.py` 逐条核验，查不到的引用即删。不得以「模型印象」补证据。
2. **留出样本隔离**。2 篇真文在规则冻结前不参与任何拆解、修订或评分——防止全样本过拟合，复测时才有没被污染的裁判。
3. **盲评由机制保证**。`blind_eval.py shuffle` 生成乱序编号文本与密钥文件，评分完成前不打开密钥；tally 解盲后输出分组均值、配对胜负与门槛核对。
4. **事实优先序**。内容真实性 > 任务明确要求 > 文风规则。风格永远不能成为编造事实、数据、经历的借口；规则只迁移表达方式，禁止复制原作者身份元素。

## 安装

适用于支持 SKILL.md 约定的编码代理（Claude Code、ZCode 等）：

```bash
git clone https://github.com/kerwin-li-8888/writing-style-extractor.git
# 整目录拷入 agent 的用户级 skills 目录，例如：
cp -r writing-style-extractor ~/.claude/skills/          # Claude Code
cp -r writing-style-extractor ~/.zcode/skills/           # ZCode
```

不用 agent 也可以：[references/methodology.md](./references/methodology.md) 是完整方法论，[templates/](./templates/) 十套模板可手动填写，[scripts/](./scripts/) 四个脚本可独立运行（仅依赖 Python 3 标准库）。

## 快速开始

**只有一篇文章**

1. 把文章放进一个目录，正文干净、能确认来源；
2. 对 agent 说「**只有一篇文章，提取文风并生成配套包**」；
3. skill 会按单篇候选路线拆证据、生成包，并提示你用一份同类型新材料试写；
4. 试写后由你评价，再决定要不要补样本走完整验证。

**有 8-10 篇文章**

1. 准备目标作者的文章（正文干净、能确认亲笔），放进一个目录；
2. 对 agent 说「**拆解文风 / 新建文风档案 / 提取某作者的写作风格**」；
3. skill 会扫描档案目录推断当前阶段、从断点续跑，每道闸门等你确认后再推进；
4. 走完五道闸门，得到一个带验证边界的规则包，可直接部署给任何模型使用。

## 脚本工具

| 脚本 | 命令 | 作用 |
|---|---|---|
| style_stats.py | `python scripts/style_stats.py <分析文本目录>` | 统计签名：单句段率、平均段长、句长分布等，产出可贴进证据表 |
| evidence_check.py | `python scripts/evidence_check.py <证据表.md> <分析文本目录>` | 证据引用回查，查不到即报错退出 |
| blind_eval.py | `python scripts/blind_eval.py shuffle <输出目录>`<br>`python scripts/blind_eval.py tally <盲评包目录>` | 生成乱序盲评包与密钥；评分完成后解盲计分、核对门槛 |
| package_check.py | `python scripts/package_check.py <文风包目录>` | 配套包结构检查：组件、JSON、规则编号、映射、证据与依赖；有效包返回 0 |

四个脚本都只依赖 Python 3 标准库。`package_check.py` 只做结构与字段检查，不证明文风效果或内容真实；未实际运行检查器时，交付记录不得写「包结构检查已通过」。

## 边界与红线

- **本仓库不包含任何真实作者样本**。样本由使用者自备，并自行负责其来源合法性与使用授权；产出的规则包同样不应附带原文分发。
- 规则只迁移**表达方式**。原作者的自称、栏目标签、互动话术、标志性收尾句属于身份元素，禁止复制。
- 「五项门槛全部通过」只构成**可用候选版本**；冻结为正式基线必须由用户明示确认，模型无权自行晋升。单篇候选不能晋升正式基线。
- 每个规则包都带验证边界声明（适用体裁、篇幅、已验证/未验证场景），外推使用风险自负。

## 验证状态（截至 v0.4.0）

- **单篇候选路线**：1 篇样本生成 V0.5 候选包（12 条规则、1 个样本）；`package_check.py` 返回 0，`evidence_check.py` 回查 68 条引用全部通过，`style_stats.py` 输出单篇统计；随后用同类型新材料完成一次真实试写，经使用者确认。
- **少样本候选路线**：2 篇同主题样本独立生成另一套 V0.5 候选包，同样完成结构检查与一次真实试写。
- **完整验证路线**：10 篇样本、66 条证据观察、24 条规则（核心 10 + 条件 16）、24 篇对照试验，独立复测 6/6 配对全胜，五项验收门槛全部通过，晋升为正式基线。
- **脚本**：四个脚本在真实档案与配套包上实测；`package_check.py` 对有效包返回 0，对缺少准备组件、核心规则缺材料处理、依赖指向包外、范文观察缺证据、通用方法带样本引用、JSON 语法错误、规则编号重复等坏样本均返回非零。

以上为维护者在自己材料上的验证记录，不是第三方独立复现；候选包不等于正式基线，具体适用边界以各包内的 `style-contract.json` 为准。
