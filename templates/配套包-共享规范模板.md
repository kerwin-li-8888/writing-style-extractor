# 共享规范模板：{style-id}/references/style-contract.json

> 对应 `references/paired-package-spec.md` 第三节。字段名、类型与允许值不得自行改名；本模板、规格与 `package_check.py` 三处必须一致。
> 用法：把下面 json 代码块另存为 `references/style-contract.json`，替换 `{...}` 占位并删除本说明。示例中的 `S01-P05` 只是格式占位，生成时必须换成真实回查得到的引用，不能照抄。

## 填写核对

- [ ] `style_id` 与包目录名、`SKILL.md` 的 `name` 一致。
- [ ] `style_version` 与 `status` 分开写；候选包 `status` 只写 `候选`；包版本由本次提取确定（如 `V0.5`），不与提取器版本混用。
- [ ] `sample_count` 等于 `sample_ids` 数量；重复文章与同一文章的改写版本不重复计数。`sample_count` 为 1 时是单篇候选，`source_boundary` 必须写明只覆盖该篇、不声称作者稳定风格或跨题材泛化。
- [ ] 每条规则 12 个字段齐全：`rule_id`、`name`、`basis_type`、`evidence_refs`、`basis_note`、`feature_group`、`default_enabled`、`conditions`、`rewriting_action`、`required_materials`、`preparation_action`、`final_check`。
- [ ] `范文观察` 至少一条真实 `S{nn}-P{nn}` 引用；`通用执行方法` 与 `用户反馈适配` 的 `evidence_refs` 为空，`basis_note` 写明来源性质。
- [ ] `required_materials` 为空时，`preparation_action` 说明无需新增材料及核对什么。
- [ ] `feature_group` 取 `核心`／`条件`／`可选`；可选动作通常 `default_enabled: false`，不默认全开。
- [ ] `resources` 只指向包内 `references/`，`external_dependencies` 为空。
- [ ] 不写入范文全文、原作者身份话术、特定案例专属数值、旧稿路径或维护记录路径。
